# GPS P0 — Production-ში გაშვების და დაბრუნების გეგმა

ეს გეგმა მხოლოდ აკაკის ცალკე, ახალი თანხმობის შემდეგ სრულდება. თითოეული ფაილი ერთ
ტრანზაქციად ეშვება: ჯერ ამოწმებს, რომ Production ისეთივეა, როგორიც 2026-11-04-ის
backup-ში; ბოლოს ამოწმებს შედეგს. თუ რომელიმე შემოწმება ვერ გაიარა, ყველაფერი უკან
ბრუნდება და არაფერი იცვლება. ჩანაწერებს (ჯავშნები, მდებარეობები, მარშრუტები)
არცერთი ფაილი არ ცვლის.

ფაილები აწყობილია `bash docs/gps-p0-release/build.sh`-ით. ხელით არ შეიცვალოს.

   GPS ცხრილები, წესები, ფუნქციები, cron. დაშიფრული ასლი იგივე ადგილას ინახება:
   `D:\KEKE-BACKUPS\`.
2. დრო: ღამე ან დილით ადრე (თბილისით 01:00–06:00), როცა მიმდინარე ტური ცოტაა.
   მიმდინარე ტურების სია (წაკითხვა): `select id, date_display, updated_at from public.bookings where status = 'in_progress' order by date_display;`
   — დიდი ხნის წინ დაწყებული და დაუხურავი ტური ჯერ KEKE-მ დახუროს (GPS-ის მეთვალყურე
   მას ისედაც აღარ აწუხებს: ტურის ბოლო დღიდან 12 საათის შემდეგ ტური „დატოვებულად“ ითვლება).
3. აპის ახალი ვერსია (OTA) ჯერ **არ** ეშვება. სერვერი ძველ აპებსაც იცავს; OTA

## 5. დაკვირვება (30 წუთი, შემდეგ ყოველდღე ერთი კვირა)

- რა გამოტოვა სერვერმა (მდებარეობა/მარშრუტის წერტილი), დღეების მიხედვით:
  `select day, kind, n from public.gps_skip_counts order by day desc, kind;`
  ფონური მდებარეობები ძველი აპებიდან ტურის შემდეგ — მოსალოდნელია. მარშრუტის
  წერტილების ნახტომი (ასობით დღეში), როცა ტურები ჩვეულებრივ მიდის, = გაჩერება და გამოკვლევა.

- `select jobname, status, start_time from cron.job_run_details d join cron.job j using (jobid) where jobname in ('gps-tidy-pins', 'watch-trip-gps') order by start_time desc limit 10;`
  — ორივე `succeeded`.
- პირველი გასუფთავების შემდეგ: `select count(*) from public.driver_locations;` —
  დარჩება მხოლოდ მიმდინარე ტურის მძღოლები და ბოლო 24 საათის ღია ეკრანები.
- რეალური მოწყობილობით (ცალკე, აუცილებელია): კომპანიის ანგარიშით მიმდინარე ტური —
  მძღოლი ჩანს; ტურის დასრულების შემდეგ — აღარ; ფლოტის მფლობელი და ადმინი — იგივე.
